1 · Empat angka yang cukup

MetrikPertanyaan yang dijawabCara hitung
hit@kApakah chunk yang benar masuk kandidat?Persentase pertanyaan yang file sumbernya muncul di k teratas
MRRSeberapa tinggi posisi chunk benar?Rata-rata 1/rank kemunculan pertama yang benar
Validitas sitasiApakah jawaban menunjuk sumber nyata?Persentase jawaban yang semua sitasinya ada di daftar sumber terambil
Penolakan benarApakah sistem berani bilang tidak tahu?Pertanyaan di luar korpus dijawab dengan penolakan, bukan karangan

Dua yang pertama mengukur retrieval. Dua yang terakhir mengukur generation. Memisahkan keduanya adalah inti dari sesi ini: tanpa pemisahan, kamu tidak tahu harus memperbaiki yang mana.

2 · Harness evaluasi

Cukup satu file Node, tanpa dependency. Isi cases dari eval/questions.md.

const BASE = process.env.BASE_URL;

const cases = [
	{ q: "Apa itu chunk overlap?", source: "catatan/rag.md" },
	{ q: "Berapa dimensi bge-m3?", source: "catatan/cloudflare.md" },
	{ q: "Apa warna langit di Mars?", source: null }, // harus ditolak
];

function mrr(ranks) {
	const scored = ranks.map((r) => (r > 0 ? 1 / r : 0));
	return scored.reduce((a, b) => a + b, 0) / scored.length;
}

let hits = 0;
const ranks = [];

for (const c of cases) {
	const res = await fetch(`${BASE}/search?q=${encodeURIComponent(c.q)}`);
	const { results } = await res.json();

	const rank = results.findIndex((r) => r.source === c.source) + 1;
	ranks.push(c.source ? rank : 0);
	if (c.source && rank > 0) hits += 1;

	const chat = await fetch(`${BASE}/chat`, {
		method: "POST",
		headers: { "content-type": "application/json" },
		body: JSON.stringify({ question: c.q }),
	});
	const { answer, sources } = await chat.json();

	const cited = [...answer.matchAll(/\[([^\]]+)\]/g)].map((m) => m[1]);
	const invalid = cited.filter((s) => !sources.includes(s));
	const refused = /tidak ada di dokumen/i.test(answer);

	console.log(JSON.stringify({
		q: c.q,
		rank,
		invalid,
		refused,
		expected_refusal: c.source === null,
	}));
}

console.log("hit@6:", hits / cases.filter((c) => c.source).length);
console.log("mrr:", mrr(ranks));

Jalankan setiap kali kamu mengubah chunking, topK, prompt, atau model. Simpan hasilnya dalam file dengan tanggal — bukan di kepala.

Kenapa bukan LLM-as-judge dulu

Menilai jawaban dengan model lain menambah biaya, latency, dan bias yang sulit dilacak. Untuk 10–30 pertanyaan, mata manusia lebih akurat. Pakai judge otomatis setelah korpusmu terlalu besar untuk diperiksa manual, dan kalibrasi dulu dengan penilaianmu sendiri.

Urutannya selalu dari atas ke bawah. Memperbaiki prompt saat retrieval masih meleset sama dengan mengecat dinding yang belum dibangun.

4 · Biaya: rumus dan angka nyata

biaya = (token_input × harga_input + token_output × harga_output) / 1.000.000

Asumsi: 6 chunk × 400 token = 2.400 token konteks, 300 token instruksi + riwayat, output 300 token. Total input ≈ 2.700 token.

ModelPer pertanyaan1.000 pertanyaan

Tiga hal yang biasanya mengejutkan:

  • Output mendominasi. Harga output 5–10× harga input. Memangkas max_tokens dari 1.000 ke 400 menghemat lebih banyak daripada memotong dua chunk.
  • Retrieval bukan biaya utama. Embedding seluruh korpus 1 juta token hanya sekitar $0,012.
  • Reranker hampir gratis. $0,003 per juta token; 20 chunk pendek per pertanyaan tidak terasa di tagihan.

5 · Observability dengan AI Gateway

Agar biaya bisa diatribusikan, lewatkan panggilan model melalui gateway dan sertakan metadata:

const res = await env.AI.run(model, input, {
	gateway: {
		id: "rag",
		metadata: { experiment: "rerank-on", question_id: id },
	},
});

const logId = env.AI.aiGatewayLogId;

Dengan begitu kamu bisa membandingkan biaya dan latency antar eksperimen tanpa menebak. Nilai metadata harus string.

Ubah satu variabel per run. Kalau kamu mengubah chunking dan model sekaligus, kamu tidak akan tahu mana yang menolong — dan kemungkinan besar akan menyimpulkan hal yang salah.

7 · Latihan

  1. Jalankan harness, catat hit@6, MRR, dan validitas sitasi sebagai baseline bertanggal.
  2. Lakukan satu eksperimen dari tabel di atas.
  3. Tulis dua kalimat: apa yang berubah, dan apakah kamu akan mempertahankannya.
  4. Hitung biaya 1.000 pertanyaan dengan model yang kamu pakai.
Hasil sesi ini

Kamu punya baseline yang bisa dibandingkan, tahu di lapisan mana sistem gagal, dan tahu harga satu pertanyaan dalam rupiah maupun dolar.

8 · Cek pemahaman

Dari memori: file sumber benar muncul di konteks, tapi jawaban tetap salah. Apa yang kamu periksa lebih dulu?

Bukan retrieval — itu sudah terbukti benar. Periksa prompt (apakah konteks jelas diberi label), urutan chunk (yang paling relevan sebaiknya di awal), max_tokens (apakah jawaban terpotong), dan baru kemudian model. Kalau jawaban tetap salah dengan konteks yang tepat, biasanya masalahnya instruksi, bukan kapasitas model.

1. Metrik mana yang mengukur retrieval saja?

2. Konteks benar ada di prompt, jawaban tetap salah. Lapisan mana yang diperbaiki?

3. Kenapa hanya satu variabel diubah per eksperimen?

4. Komponen biaya mana yang biasanya paling besar?
