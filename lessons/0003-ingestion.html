2 · Ekstraksi

env.AI.toMarkdown() menerima file dan mengembalikan markdown beserta perkiraan jumlah token. Untuk PDF hasil scan ia menjalankan OCR; untuk gambar, model vision mengekstrak teksnya.

export class ObjectNotFoundError extends Error {
	constructor(key: string) {
		super(`Tidak ada objek: ${key}`);
		this.name = "ObjectNotFoundError";
	}
}

export async function extract(env: Env, key: string): Promise<string> {
	const obj = await env.DOCS.get(key);
	if (!obj) throw new ObjectNotFoundError(key);

	// Markdown dan teks polos dibaca apa adanya; format lain lewat toMarkdown.
	if (/\.(md|txt|markdown)$/i.test(key)) {
		return await obj.text();
	}

	const [result] = await env.AI.toMarkdown([
		{
			name: key,
			blob: new Blob([await obj.arrayBuffer()]),
		},
	]);

	if (!result) throw new Error(`Konversi gagal: ${key}`);
	if (result.format === "error") throw new Error(result.error);
	return result.data;
}

Selalu kirim array, walau hanya satu file: input array mengembalikan array, input objek mengembalikan objek — destructuring akan gagal pada yang kedua.

Untuk .md dan .txt, teks dibaca langsung. toMarkdown hanya dipakai untuk format yang memang perlu dikonversi (PDF, DOCX, gambar), sehingga tidak ada neuron yang terbuang untuk file yang sudah berupa teks. Error khusus ObjectNotFoundError dipetakan menjadi HTTP 404 di route, bukan 500 — objek yang tidak ada adalah kesalahan input, bukan kerusakan server.

Kenapa R2 dulu

File asli adalah sumber kebenaran. Kalau chunking-mu berubah, kamu tidak perlu meminta dokumen lagi ke pengguna — cukup baca ulang dari R2. Menyimpan hasil ekstraksi saja berarti kamu tidak bisa memperbaiki ekstraksi di masa depan.

3 · Chunking

Tujuannya bukan memotong serapi mungkin, tapi memastikan setiap chunk berdiri sendiri saat muncul di prompt tanpa konteks sekitarnya.

function chunkText(text: string, size = 1200, overlap = 200): string[] {
	const paragraphs = text
		.split(/\n{2,}/)
		.map((p) => p.trim())
		.filter(Boolean);

	const chunks: string[] = [];
	let buf = "";

	for (const p of paragraphs) {
		if (buf.length > 0 && buf.length + p.length + 2 > size) {
			chunks.push(buf.trim());
			buf = buf.slice(Math.max(0, buf.length - overlap)).trim() + "\n\n";
		}
		buf += p + "\n\n";
	}
	if (buf.trim()) chunks.push(buf.trim());
	return chunks;
}

Ukuran dihitung dalam karakter, bukan token. Untuk teks Indonesia, satu token kira-kira 3–4 karakter, jadi 1.200 karakter ≈ 300–400 token. Itu rentang yang aman: cukup untuk satu argumen utuh, cukup kecil untuk tidak membanjiri prompt.

Overlap 200 karakter menyelamatkan kalimat yang terpotong di batas chunk. Overlap terlalu besar membengkakkan biaya embedding karena teks yang sama di-embed berkali-kali — 10–20% sudah cukup.

Batas pendekatan ini

Satu paragraf yang lebih panjang dari size akan lolos apa adanya. Itu bisa diterima untuk catatan pribadi; kalau korpusmu berisi tabel atau dokumen hukum, tambahkan pemotongan paksa per kalimat.

4 · Identitas yang stabil

async function sha256(text: string) {
	const digest = await crypto.subtle.digest(
		"SHA-256",
		new TextEncoder().encode(text),
	);
	return [...new Uint8Array(digest)]
		.map((b) => b.toString(16).padStart(2, "0"))
		.join("");
}

ID vektor: ${source}#${i}. Stabil antar-run, jadi upsert menggantikan vektor lama alih-alih menambah duplikat. Hash isi disimpan di D1 untuk melewati chunk yang tidak berubah:

const ids = batch.map((_, j) => `${key}#${i + j}`);
const existing = await env.DB
	.prepare(`SELECT id, hash FROM chunks WHERE id IN (${ids.map(() => "?").join(",")})`)
	.bind(...ids)
	.all<{ id: string; hash: string }>();

const hashById = new Map(existing.results.map((r) => [r.id, r.hash]));
const todo = batch.filter((_, j) => hashById.get(ids[j]) !== hashes[j]);

if (!todo.length) continue; // semua chunk sudah sama

Ini yang membuat ingestion idempotent: menjalankan ulang proses yang sama tidak mengubah keadaan akhir. Tanpa ini, setiap kali kamu meng-upload dokumen yang sama, biaya embedding naik dan hasil pencarian mulai berisi duplikat.

5 · Rekonsiliasi: hapus yang tidak lagi ada

Upsert hanya menyentuh ID yang kamu kirim. Kalau dokumen menyusut — atau strategi chunking berubah sehingga jumlah chunk berkurang — ID lama tidak pernah dikirim lagi, dan tidak ada yang menghapusnya. Hasilnya: chunk yatim yang isinya sudah tidak ada di sumber, tetap bisa muncul di jawaban.

Ini bukan teori. Saat menjalankan rag-app, dokumen tiga chunk dipendekkan menjadi satu chunk: D1 masih berisi tiga baris, dan chunk lama tetap menjadi hit teratas. Test API menangkapnya sebagai 3 !== 1.

const expected = new Set(chunks.map((_, i) => `${key}#${i}`));
const { results: existing } = await env.DB
	.prepare("SELECT id FROM chunks WHERE source = ?")
	.bind(key)
	.all<{ id: string }>();

const orphans = existing.filter((r) => !expected.has(r.id)).map((r) => r.id);

if (orphans.length) {
	await env.DB.batch(
		orphans.map((id) => env.DB.prepare("DELETE FROM chunks WHERE id = ?").bind(id)),
	);
	await env.INDEX.deleteByIds(orphans);
}
Urutan penting

Hapus di D1 dulu, baru vektor. Kalau vektor dihapus lebih dulu lalu proses mati, D1 masih mengira chunk itu ada dan ingest berikutnya akan melewatinya karena hash cocok — vektornya hilang permanen. D1 yang sudah bersih juga membuat chunk yatim tidak bisa lagi ditampilkan meski vektornya belum sempat terhapus.

Operasi hapus di Vectorize asinkron seperti upsert: beri waktu sebelum menyimpulkan gagal. Di rag-app, respons ingest menyertakan deleted berisi jumlah chunk yang dibersihkan, dan test API memeriksa D1 segera serta Vectorize dengan retry.

Urutan yang tidak bisa dibalik

Metadata index harus dibuat sebelum vektor di-upsert. Vektor yang masuk sebelum metadata index ada tidak akan bisa difilter; satu-satunya perbaikan adalah meng-upsert ulang semuanya.

Beri waktu. Propagasi Vectorize bisa sampai semenit, dan vektor hasil upsert ulang baru bisa difilter setelah propagasi itu selesai.

String yang bisa difilter hanya 64 byte pertama. Simpan source sebagai path pendek (catatan/rag.md), bukan URL panjang.

7 · Ingestion sebagai Workflow

Ingestion tidak boleh berjalan di dalam request handler. Workers Free hanya memberi 10 ms CPU per request, dan meng-embed ratusan chunk butuh waktu. Workflow memberi kamu langkah-langkah yang tahan gagal: kalau langkah ke-7 mati, langkah 1–6 tidak diulang.

import { WorkflowEntrypoint } from "cloudflare:workers";
import type { WorkflowEvent, WorkflowStep } from "cloudflare:workers";
import { ingestDoc } from "./ingest";

export class IngestWorkflow extends WorkflowEntrypoint<Env, { key: string }> {
	async run(event: WorkflowEvent<{ key: string }>, step: WorkflowStep) {
		const { key } = event.payload;

		return await step.do(`ingest ${key}`, async () => {
			return ingestDoc(this.env, key);
		});
	}
}

Satu langkah = satu dokumen. Kalau langkah itu gagal, Workflow mengulanginya tanpa menyentuh langkah lain. Batch 20 chunk dan rekonsiliasi sudah ada di dalam ingestDoc, jadi tidak diduplikasi di sini. Untuk dokumen yang sangat besar, pecah menjadi beberapa step.do agar retry tidak mengulang seluruh dokumen.

Di rag-app, ingestDoc dipanggil inline dari route supaya bisa diuji tanpa deploy. Workflow ini adalah pembungkus produksinya dan belum dijalankan di sana.

Picu dari route kecil:

export { IngestWorkflow } from "./ingest";

if (path === "/ingest" && request.method === "POST") {
	const { key } = (await request.json()) as { key?: string };
	if (!key) return json({ error: "key wajib" }, 400);

	const instance = await env.INGEST.create({ params: { key } });
	return json({ id: instance.id }, 202);
}

Baris ekspor itu wajib: Workflow hanya dikenali kalau kelasnya diekspor dari entry module yang ditunjuk main di wrangler.jsonc.

8 · Latihan

  1. Upload tiga dokumen ke R2: npx wrangler r2 object put rag-docs/catatan/a.md --file a.md.
  2. Picu ingestion untuk ketiganya.
  3. Catat jumlah baris: npx wrangler d1 execute rag --remote --command "SELECT source, COUNT(*) FROM chunks GROUP BY source".
  4. Jalankan ulang ingestion untuk dokumen yang sama.
  5. Pastikan jumlah barisnya tidak berubah.
  6. Pendekkan salah satu dokumen, ingest ulang, lalu pastikan jumlah chunk-nya turun dan respons memuat deleted lebih dari nol.
  7. Bonus: integrasikan pemeriksaan hash dari bagian 4 ke dalam langkah embed, supaya chunk yang isinya tidak berubah tidak di-embed ulang.
Hasil sesi ini

Korpusmu ada di Vectorize dan D1, dengan ID yang stabil, ingestion yang bisa diulang, dan chunk lama yang ikut terhapus saat dokumen berubah.

9 · Cek pemahaman

Dari memori: kenapa ID vektor harus deterministik?

Karena upsert memutuskan "ganti atau tambah" berdasarkan ID. ID acak berarti setiap run menambah salinan baru; ID stabil berarti run berikutnya memperbarui yang sudah ada. Ini juga yang membuat retry pada Workflow aman.
